# Phase 5 security review (2026-10-05)

Everything added in Phase 5 (since the Phase 4 review, commit `a4ebaf4`), with special attention to what leaves the device and what reads outside input: AI reading (ADR 0009), transfer files away from home (ADR 0006, 5c), saved emails, voice notes, files written without encryption, the protected emergency summary, privacy between users (HH-11), permissions, the phone, and the libraries added. Same standard as the Phase 3 and Phase 4 reviews: what leaves the device is only what the user asked to send; outside input cannot use up memory, time or the file system; core.db, which every user of the household can read, holds no amounts, names of private records, typed text or file names.

## Findings and fixes

| # | Severity | Finding | Fixed |
|---|---|---|---|
| 1 | Medium | **AI reading, hidden areas.** A hidden area was replaced by blocks of its average colour, each half the area's height. On a line of text that leaves about one block per character, and pixelation of a known font can be reversed (as tools such as Depix do), so part of a card or account number could have been recovered from the picture sent to Anthropic. | Hidden areas are now filled with one flat grey (the grey the preview shows), whatever was under them. `AiReadingTest` checks that two different numbers give the same pixels. |
| 2 | Medium | **Protected emergency and health summary.** The PDF was encrypted with AES-128, whose PDF key comes from the password through MD5: a lost file can be tried against millions of passwords a second. | AES-256 with the PDF 2.0 security handler (revision 6, SHA-2 password hashing). `SectionsPdfTest` checks the handler. |
| 3 | Low | **Files written without encryption without saying so.** The emergency or health summary saved without a password, the year-end package folder (summaries plus copies of the slips and receipts) and scheduled report PDFs gave no warning, unlike the full export. | Each now says, in red, that the file is not encrypted (EN and FR). |
| 4 | Low | **Saved emails (.eml).** No limit on size, nesting or number of parts; the HTML-to-text regular expressions took quadratic time on malformed HTML (`<script` repeated, `<` repeated), enough to hold the import for hours; a character reference past U+10FFFF threw; an attachment's name could carry a folder (`../../x.pdf`, `C:\...`), kept as the document's file name and later used to suggest where to save it. | At most 50 MB, 8 levels and 200 parts; HTML at most 2 million characters, read in one pass; invalid references dropped; attachment names keep only their last part, without control characters. `EmailMessageTest` covers each. |
| 5 | Low | **Document file names from outside** (an email attachment, a phone) were stored as given. The year-end package then used the part after the last dot as the extension of the copy it writes, so a name such as `x.pdf:hidden` or `x.a\b` could write an NTFS alternate stream or aim at a subfolder; a person or document named `..` would have put the copies in the parent folder. | Imported names keep only their last part (`importedFileName`); the package uses `plainFileName` (no separators, reserved characters or dots at the ends) and an extension of letters and digits only. |
| 6 | Low | **Transfer folder (desktop).** Anyone who can write to the cloud folder can leave files there: a request file of any size was read whole into memory; an unexpected failure on one file stopped the files after it; old replies were removed by the prefix `to-phone` alone, so a user's own file named, say, `to-phone-list.docx` would have been deleted after 60 days. | Files over 200 MB (the Wi-Fi limit) are moved to `Not imported` unread, also when imported by hand; one file's failure is reported and the others go on; only `to-phone-*.roostsync` regular files are removed. `TransferFolderTest`. |
| 7 | Low | **Transfer folder (phone).** A reply file was read whole, whatever its size. | At most 20 MB is read (with a bounded read that works on Android 10); a larger file is not a reply and is removed like any unreadable one. |
| 8 | Low | **Voice notes.** Whatever came as a capture's voice note was stored as `audio/wav` and given to the Java sound system to play, without a size or format check. | Only a RIFF/WAVE file of 16-bit mono PCM and at most 65 seconds is kept (`VoiceWav.isVoiceNote`); the capture itself still arrives. `SyncServiceTest`. |
| 9 | Low | **Saved reports.** The upsert's `ON CONFLICT(id) DO UPDATE` did not check the owner, so saving with another user's report id would have changed their report, including the folder their scheduled PDF is written to. | The service refuses an id that is not one of the user's own, and the query updates only the same user's row. `CustomReportTest`. |
| 10 | Low | **Contacts on the phone.** A contact's website was opened with any scheme it held (`content://`, `file://`), not only a web address. | Only `http` and `https` are opened; anything else is read as a site's name. `ContactBookTest`. |
| 11 | Low | **Budget alerts on the phone** showed the amounts spent and budgeted on the lock screen, while the app itself is behind a PIN. | Private visibility with a public version that shows only the title. |
| 12 | Low | **Libraries.** Anthropic's SDK 2.68.0 brings Jackson 2.19.4, which has published advisories (OSV, 2026): DoS in jackson-core (number length in the async parser, unbounded error token, float pattern backtracking) and jackson-databind (polymorphic typing bypasses, eager DNS resolution, forward references). Jackson only reads the service's answers over TLS, and the app turns on no polymorphic typing, so the exposure was small. | Jackson raised to 2.21.7 through its BOM in `core/ai` (no advisory listed); `ClaudeProviderTest` passes with it. OkHttp 4.12.0, Okio 3.6.0, JNA 5.19.1, the SDK itself, victools 4.38.0 and the Kotlin libraries have no advisory listed. |
| 13 | Low | **About screen.** "The app goes on the internet only for..." did not name AI reading. | It now names the documents the user chooses to read with AI, sent to Anthropic with their own key (EN and FR). The privacy policy already did. |

`AuditPrivacyTest` now also covers Phase 5: contacts saved, revealed, merged and deleted, a household rate with a typed note, a category rule with a payee text and amounts, AI settings and an AI reading of a document with a chosen file name. None of the names, numbers, amounts, notes or file names reach the audit log.

## Checked and kept

- **AI key (AI-02).** Kept in Windows Credential Manager or the Secret Service under `RANN's Roost/ai/<provider>/<household>/<user>`, never in the household files, backups, settings or audit log; the key field is a password field, cleared after saving; the key is never shown, logged or put in an error message (the SDK's errors do not carry it). Where the keyring refuses, saving fails with a message: there is no plain-text fallback. The demo keeps keys in memory only. The base URL can be changed only in the demo, whose keys never come from the system store.
- **Nothing sent before Send (AI-04).** With "ask before each document" on (the default), pages are only prepared on the computer until Send; the cost estimate is computed locally. With it off, a document is sent only when the user clicks "Read with AI". The crop, hidden areas and the 2,000-pixel limit are applied to the image that is encoded and sent (`DesktopAi.prepare` feeds both the preview and the request), not only to the preview. At most 20 PDF pages.
- **Answers (AI-05).** Every answer is checked against the full schema and its sums on the computer whatever the API promises; refusals and answers cut short are reported before anything is read. The usage log (AI-06) is in the document's ledger and shows each user only their own requests; the audit log records only that a document was read and by which model.
- **Transfer files.** The public header holds the desktop and device ids, the direction and the time, as ADR 0006 says; the same ids are bound into the AES-GCM body, so a changed header fails to open. Malformed or truncated files are `NOT_A_BUNDLE` (moved aside), files of another household are left alone, files from a removed phone or one that fails to open are moved aside, a replayed request is acknowledged without importing again (item ids are recorded). Reply names come from `BundleFile.name`, whose device part is letters and digits only, and are written only into the chosen folder, through a `.part` file and an atomic move. Phone files are split at about 15 MB of content for email; shared files are sealed bundles in the app's cache, offered through a FileProvider that is not exported.
- **The phone.** No new exported component: the main activity's filters are those of Phase 2 (launcher, pairing link, shared images and PDFs), the transfer FileProvider is not exported, the GitHub build's install receiver is not exported. The folder is the user's own, chosen with the system picker; the hourly background check only collects replies. Contacts sent to the phone carry phones, emails, address, website, hours and notes, never account or client numbers (`PhoneContactService.forPhone` keeps only phone and email details); a contact made on the phone waits for review in the ledger of the phone's group and never becomes a contact by itself. Reference data is built only for the phone's own user, while they are signed in.
- **Privacy between users (HH-11).** New records (contacts and their links, phone contacts waiting, tax figures and estimates, family money, trips, contractors, projects, invoices, rentals, rewards, estate papers, AI readings and usage) are in each group's ledger. In core.db: saved reports (choices only, no amounts, each user's own), the household's rate and rule values (rates, limits and password rules, meant to be shared), each user's AI settings (on or off, ask first, model; no secret). Reports, the year in review, the tax package and custom reports read only the groups the user can open. Revealing a full account or client number asks for the password again and is logged without the number.
- **Password rules.** Set by an administrator only (`RateRuleService.add` and `delete` call `requireAdmin`); a minimum of 8 characters and Argon2id of at least 19 MiB and 2 passes are enforced when entered and again when read, so an older or edited value can never weaken them.
- **Permissions.** Write functions added in Phase 5 check the group's level in the service (`editable`, `books.require`, `requireEditor`, `requireAdmin`), not only in the screens; AI settings are refused to viewers; merging contacts needs edit rights on both groups.
- **Imported files.** The voice-note player and the document viewers read only what is in the vault; a phone's capture is opened only after its bundle is authenticated.

## Accepted, with reasons

- **The transfer header** says which household and phone a file belongs to, and when it was made, to whoever can see the cloud folder: the provider and the user. It holds no name, amount or content, and is needed to find the pair key.
- **A replayed reply** (an old reply copied back into the folder) is authentic and opens on the phone, which then shows older reference data until the next transfer. Only someone with write access to the user's own cloud folder can do it, and nothing is lost.
- **Decompression and item contents after authentication** (the gzip inside a bundle, the length of a phone contact's notes) are bounded only by the request size: only the paired phone, holding the pair key, can produce them.
- **Report exports** (CSV, Excel, PDF of any report, including custom reports and the medical bundle) are saved where the user chooses, without a warning, as every report export has been since Phase 1: they hold what is on the screen, the user picks the file, and a warning on every export would be ignored. Folders written unattended (scheduled reports) and the package with document copies now warn.
- **Printing a summary** writes an unencrypted temporary PDF for the printer, removed when the app closes; the system's print path needs a file.
- **A protected PDF's password** needs 8 characters, as the dialog says; the dialog suggests giving it separately. AES-256 with SHA-2 hashing makes guessing slower, not impossible, for short passwords.
- **Settings kept for the household** (the transfer folder, the watched folder) can be set by any user, viewers included; the desktop then only imports and removes transfer files in that folder for the signed-in user's own phones.
- **Changing core.db directly.** A household user who opens core.db with their own key could change another user's saved report folder or the household's rules; the service refuses it, but the database cannot. HH-11 protects reading; every user of a household is trusted to write the shared settings, as before.
- **Bill and maintenance reminders** on the phone show a bill's or a task's name on the lock screen, without amounts, as since Phase 2 and 4c.
- **Very large Argon2id settings** (up to 4 GiB and 50 passes) can be chosen by an administrator; they apply only to passwords set afterwards, and only an administrator can choose them.
- **AI answers** are parsed without a nesting limit: they come from Anthropic's service over TLS, and a failure is reported as an answer that could not be checked.

## Tests

New or extended: `AiReadingTest` (hidden areas), `SectionsPdfTest` (AES-256), `EmailMessageTest` (names, nesting, parts, size, linear HTML, bad references), `TransferFolderTest` (which replies are removed, size limit), `SyncServiceTest` (voice notes), `CustomReportTest` (another user's report), `ContactBookTest` (web addresses only), `AuditPrivacyTest` (Phase 5 records).
