# Development helpers

Small scripts used while building and checking the app. They are not part of the product.

| Script | Use |
|---|---|
| `add_messages.py` | `python tools/dev/add_messages.py en.txt fr.txt` appends new English and French texts; `MessageKeysTest` then checks every key exists in both. |
| `check_store_texts.py` | `python tools/dev/check_store_texts.py` checks every field in `docs/store/*.md` against its store limit (characters, items, search terms). |
| `shot.ps1` | `powershell -File tools/dev/shot.ps1 -Out screen.png` waits for the desktop app's window (a `java` process) and saves a picture of it. It also finds the installed app (`RANN's Roost.exe`); either way it captures only the app's own window. |
| `fake_anthropic.py` | `python tools/dev/fake_anthropic.py [port] [folder]` stands in for Anthropic's Messages API, so the AI reading screens can be tried in the demo (`-PaiUrl=http://127.0.0.1:8765`) without a key or cost; it saves the pictures it receives to the folder, to check what hidden areas look like when sent. |
| `manual_phone.py` | `python tools/dev/manual_phone.py en capture` saves the emulator's screen as the manual's `phone-capture.png` (see The manual's pictures below). |
| `click.ps1` | `powershell -File tools/dev/click.ps1 -X 100 -Y 200 [-Out screen.png]` clicks inside the app's window (coordinates from its top-left corner) and optionally saves a picture; `-Wheel -600` scrolls down there instead (120 per notch, positive scrolls up). |

Typical check of a screen: `./gradlew :app:desktop:runDemo -Plang=en -Psection=DOCUMENTS` in the background, then `shot.ps1`.
Android: start the emulator (`pixel_7_-_api_36_0`), `adb install -r app/android/build/outputs/apk/github/debug/android-github-debug.apk`, and `adb exec-out screencap -p > phone.png` (from Git Bash, not PowerShell, which corrupts binary output).
Trying the phone at leisure: the host listens for an hour by default; `-Pminutes=480` keeps it for 8 hours (create `app/desktop/build/phone-stop` to stop it sooner). When it stops, the host prints what the phone sent: trips with their legs, breaks, addresses and photos and notes, places saved on the phone, fill-ups and the documents in the inbox, to check a run without a window. Mock the phone's position with `adb -s emulator-5554 emu geo fix <longitude> <latitude>`.

Phone reminders: `./gradlew :app:desktop:manualPhoneHost -Plang=en -PeventIn=7` adds two events starting in 7 minutes, reminded 2 minutes before (one medical, whose notification names nothing); pair the phone within 5 minutes and watch the notification. `adb shell appops set ca.ranns.roost.mobile SCHEDULE_EXACT_ALARM allow` makes it ring on the minute.
To pair the emulator with the demo (each demo run is a new household): run the demo with `-Psection=PHONES`, click "Pair a phone", then "Copy as text", and open the copied `hfmpair:` text on the phone with `adb shell am start -a android.intent.action.VIEW -d "'<text>'" ca.ranns.roost.mobile`. The phone's screen is 1080x2400 for `adb shell input tap`.
Update screens: sign a test release with a throwaway key (`tools/release` `keygen` into a temporary folder, then `sign-release`; delete the `release-key.pub` it writes into `core/update` afterwards), put that key's `release-key.pub` beside the files, and run the demo with `-Pupdate=<folder> -Psection=ABOUT`. The demo keeps its own settings, so the first-start question appears until it is answered there.

## The manual's pictures

The manual shows pictures of the app (format: `docs/manual-format.md`). Retake them after a screen changes, English first, then French:

- Desktop: `./gradlew :app:desktop:manualScreenshots -Plang=en`, then `-Plang=fr`. It builds the sample household (Ontario in English, Quebec in French) and draws each screen, tab and dialog in the list in `app/desktop/src/screenshots/kotlin/.../ManualScreenshots.kt` offscreen, at 1280 x 860 in light colours, with the Compose test library: no window opens, nothing is clicked on the real screen, and nothing else on the computer can appear. It writes `core/i18n/src/main/resources/hfm/manual/<lang>/images/*.png` (about two minutes). `-Pshot=bills,taxes-estimate` retakes only those. Then the dark twins: the same task with `-Ptheme=dark` (EN and FR) draws the same pictures in the app's dark colours into `images/dark/` (all but `display-dark`, dark already); the manual window shows them when the app's colours are dark. `ManualTest` fails when a desktop picture has no dark twin, so retake a picture in both colours (`-Pshot=` works with `-Ptheme=dark` too). To add a picture, add a `Shot` to the list (a screen, then `click(label)` for a tab or button), run the task, and put a picture line in both languages' chapters; `ManualTest` fails on a file no chapter shows.
- So the pictures show nothing of this computer, the task uses a made-up network address on the Phones screen and a made-up `APPDATA` on the AI screen, keeps settings in memory, and puts the sample household in `%PUBLIC%\Documents\RANN's Roost` (deleted afterwards), so the Backups screen's folder names no user.
- Check a sample of the new pictures by eye before committing (English, then French): the right screen, the sample data, nothing private.
- Phone (`phone-*.png`): start the emulator (`pixel_7_-_api_36_0`), install the GitHub debug APK, clear the app (`adb shell pm clear ca.ranns.roost.mobile`) and set its language (`adb shell cmd locale set-app-locales ca.ranns.roost.mobile --locales en-CA`, or `fr-CA`). Run `./gradlew :app:desktop:manualPhoneHost -Plang=en` (or fr) in the background: the sample household listens for phones with no window and writes its pairing text to `app/desktop/build/phone-invitation.txt`. Choose the PIN 1234 on the phone, then pair with `adb shell am start -a android.intent.action.VIEW -d "'<that text>'" ca.ranns.roost.mobile`. Enter a quick expense (Tim Hortons, 8.45, Joint chequing, Restaurants) and an odometer reading (Civic, 65420), then for each screen run `python tools/dev/manual_phone.py en <name>` with the names capture, quick-expense, sent, summary, contacts and contact (Dr. Patel; in French Dre Gagnon). It saves only the phone's screen, without the status bar, 540 pixels wide in 256 colours. The phone pictures are light only; the manual shows them in dark mode too. Create `app/desktop/build/phone-stop` to stop the household. Set the app's language back with `--locales ""`.

## The store pictures

- Desktop (Microsoft Store, 1440 x 900): `./gradlew :app:desktop:storeScreenshots -Plang=en`, then `-Plang=fr`. The same offscreen drawing as the manual's pictures, of the list `STORE_SHOTS` in `ManualScreenshots.kt`, in full colour, into `docs/store/screenshots/desktop-<lang>`. The website's desktop pictures come from `-Pweb` added to the same task (dashboard, credit card register, income and expense report, into `app/desktop/build/web-images`), scaled down to 1080 x 675 JPEG for `website/images/desktop-*.jpg`.
- Phone (Google Play, 1080 x 2160, within Play's 2:1 limit): pair the emulator with `manualPhoneHost` as for the manual's phone pictures, take `adb exec-out screencap -p` from Git Bash and keep 2160 rows below the status bar. The website's phone pictures (`website/images/phone-*.jpg`, 600 x 1200) are these, scaled down.
